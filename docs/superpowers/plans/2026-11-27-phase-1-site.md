# Bisaat Club Phase 1 Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the approved "walk the floor" page live as one Next.js (App Router, TypeScript) Node app, with its content in MongoDB, a bundled fallback, a read-only content API and the security groundwork.

**Architecture:** One Next.js server. `src/content/` holds the zod schemas and the bundled seed/fallback data. `src/server/` is the only code that touches MongoDB (marked `server-only`). The page server-renders the header and sheet from `getSiteContent()`; a client component runs the walk-through. The walk-through (`src/walkthrough/`) talks to the room only through a `RoomRenderer` interface; today's implementation is the code-drawn room in `src/scene/procedural/` (geometry and shader in separate modules), which can later be swapped for 360° photos or a modelled scene.

**Tech Stack:** Next.js 16 (App Router, `proxy.ts`), React 19, TypeScript strict, `mongodb` 7 driver, `zod` 4, Vitest, Playwright, MongoDB 8 in Docker for development, `tsx` for scripts.

**Spec:** `bisaat-club-coding-agent-prompt.md` (the brief). The design specification is `bisaat-club-walk-the-floor.html` (the approved reference page; read its source).

## Global Constraints

- Port the reference page faithfully. Do not redesign it, restyle it or "improve" the copy. CSS, markup structure, ids, class names, copy, geometry, shader source and interaction constants are copied verbatim from `bisaat-club-walk-the-floor.html`.
- Single Next.js app serving site and API from one Node server. No `output: 'export'`, no separate frontend/backend.
- Phone first: at 390×844 the page must match the reference in light and dark at all six viewpoints; differences limited to font rendering.
- The browser never talks to MongoDB. All DB access lives under `src/server/` and imports `server-only`.
- Secrets only in env vars. Commit `.env.example` with names only. No secret in the client bundle or logs (never log a connection string).
- Reject any input containing keys that start with `$` or contain `.`.
- No public write endpoints. `/admin` (and `/admin/*`) and every non-GET `/api/*` request are refused.
- Do not add authentication libraries, booking models, payment SDKs or placeholder pages.
- Booking button href and label each read from one setting (`settings.bookingUrl`, `settings.bookingLabel`).
- Homepage must render if the database is unreachable, from the bundled seed data. Content reads are cached with revalidation (60 s), not queried per request.
- DM Sans via `next/font` (self-hosted, so the CSP needs no Google hosts).
- Brand colours: ink `#1F2A44`, cream `#F3EBDD`, walnut `#5A3A24`, amber `#E3A33B`, deep amber `#C8821B`, wood `#91705A`, espresso `#2B1D15`.
- Local dev: `docker compose up -d` (MongoDB) then `npm run dev`. No hosting-specific assumptions.
- Commits: author is the repo-local git identity; end every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Database stopped, or a stored document fails schema validation → homepage still renders the bundled content, no 500 (tests in Task 3).
- Deep links with unknown or partial hashes (`#foo`, `#night`, `#lib-day`, `#door-night`) behave exactly as the reference (Task 7 unit test of `parseDeepLink`).
- Query strings with operator-style keys (`/api/content?$where=1`, `?a.b=1`) → 400, never reach the data layer (Task 4).
- WebGL unavailable → `#nogl` message shown, hint and hotspots hidden, sheet still works (Task 7, e2e in Task 9).
- Bursts of API requests from one IP → 429 with `Retry-After` after the limit; page routes are not rate limited (Task 5).
